// the engine

Built to ship games, not toy demos

Multi-engine fluency

Luau, C#, GDScript, and C++ from one conversation. Same idea, natively compiled for every target.

Universal map schema

Kodr emits kodr-map-v1 JSON — heightmap, spawns, lighting, rules — compiled to any engine with one command.

Systems, not snippets

Inventories, combat, saving, round logic, AI. Whole gameplay systems with server-authoritative logic where it matters.

Game-feel tuning

Coyote time, hit-stop, camera look-ahead. The invisible 20% that makes games feel professional.

Truly yours

A single standalone checkpoint. The reference model is deleted after training — no vendor lock-in, no runtime dependency.

Open, always

Apache-2.0. The training data and pipeline are public. Fork it, retrain it, ship it.

// faq

      
Questions, answered

    

    

      

        Is Kodr really trained from scratch?
        
Kodr's weights are the result of fine-tuning an open Qwen3-class reference model and merging the adapter in — so the shipped checkpoint depends on nothing at inference time. The "build from scratch" philosophy applies to the product: data, pipeline, weights, and UI are all public.

      

      

        Does it work without a GPU?
        
Chat over the free Hugging Face playground: yes. Generating maps and scripts locally: the 27B model runs on CPU via llama.cpp. Training from scratch needs a GPU — the Colab notebook sizes itself to the GPU it finds.

      

      

        Can I retrain it on my own games?
        
Yes. Drop JSONL chat examples into model/dataset/, rebuild, retrain. The whole pipeline is in this repo.

      

      

        What's the license?
        
Apache-2.0 — use it in commercial games, mod it, retrain it, ship it.
